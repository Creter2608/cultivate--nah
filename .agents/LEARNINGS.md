# Project Learnings & Pitfalls Log

This document serves as the project's cumulative memory of mistakes, bugs, architectural missteps, and technical pitfalls ("vấp ngã"). 

## Protocol for AI Agents & Developers
1. **Read Before Coding**: Always review the relevant sections below before designing or implementing a subsystem.
2. **Log Every Mistake**: Whenever a non-trivial bug, regression, runtime crash, or architectural redesign occurs, document it immediately using the format below.
3. **Never Repeat a Logged Pitfall**: Violating a logged rule is considered a regression defect.

## Historical Pitfalls & Lessons Learned

### [2026-08-28] GDScript 2.0 Static Typing vs. Untyped Signals
- **Area**: Godot Engine / GDScript
- **Context**: Emitting events across scenes via signals and Autoloads.
- **The Stumble / Symptom**: Signals emitted with generic `Variant` arguments cause silent runtime crashes or autocomplete loss in listener scripts when refactoring property types.
- **Root Cause**: GDScript signals without explicit parameter type declarations allow any payload, bypassing static analysis at parse time.
- **Fix & Prevention Rule**:
  - Always declare typed signal parameters: `signal health_changed(new_health: float)` instead of `signal health_changed(new_health)`.
  - Signal names MUST strictly use `snake_case` in GDScript.

---

### [2026-08-28] Mobile Touch Target Size Failures on Small Screens
- **Area**: Mobile UX / UI Design
- **Context**: Designing buttons and interactive UI for portrait mobile layout (720x1600).
- **The Stumble / Symptom**: Buttons scaled to desktop pixel dimensions (e.g. 24-32px) are nearly impossible to tap accurately on mobile screens and lead to mis-clicks.
- **Root Cause**: Designing UI visually without accounting for the physical average human finger touch target area (~7-10mm).
- **Fix & Prevention Rule**:
  - All interactive touch hitboxes MUST be at least 48x48px (preferably 56px).
  - Use `custom_minimum_size` on `Button` / `TextureButton` nodes and configure `TextureRect` inside containers properly.

### [2026-08-28] Direct Parent Node Coupling in Sub-Components
- **Area**: Architecture
- **Context**: Child components (like `HealthComponent` or `InteractionArea`) needing to notify the parent character of state changes.
- **The Stumble / Symptom**: Calling `get_parent().take_damage()` crashes when the component is instanced inside a test scene or reorganized in the node tree.
- **Root Cause**: Violation of the Godot principle: *"Call down (methods), Signal up (events)"*.
- **Fix & Prevention Rule**:
  - Components MUST NOT call `get_parent()` or `owner` directly.
  - Components emit typed signals upward; the parent node or scene connects to those signals in `_ready()`.

### [2026-08-28] CLI Test Suite Assumptions in Godot Projects
- **Area**: Tooling / Verification
- **Context**: Running verification steps during Subagent-Driven Development (SDD).
- **The Stumble / Symptom**: Generic subagent prompts attempting to execute standard CLI unit tests (`npm test`, `pytest`) fail because Godot 4 uses scene-based and headless engine runs.
- **Root Cause**: Generic web/backend workflows assumed standard language test runners exist out of the box.
- **Fix & Prevention Rule**:
  - Use `godot-verification-prompt.md` for static analysis, scene isolation validation (F6), and headless checks (`godot --headless --check-only`).

### [2026-08-28] Layer 1 Overreach & Semantic Code Intervention Violation
- **Area**: Tooling / Multi-Agent Pipeline
- **Context**: Executing Fast-Path code synthesis via DeepSeek Coder (Layer 3).
- **The Stumble / Symptom**: Layer 1 (Host/Gemini) intervened with its own reasoning to edit, filter, and rewrite code generated by DeepSeek before writing to disk, directly violating the mechanical operator constraint.
- **Root Cause**: Instruction drift and cognitive overreach — Host AI attempted to "fix" or "improve" specialized model outputs instead of deterministically applying them and relying on verification feedback loops.
- **Fix & Prevention Rule**:
  - Layer 1 MUST act strictly as a deterministic I/O operator: Take exact generated code from DeepSeek $\rightarrow$ Write directly to disk $\rightarrow$ Run mechanical verification.
  - If DeepSeek output is flawed or fails verification, Layer 1 MUST pass the raw compiler/test error back to DeepSeek for 1 retry (Hard Cap = 1) instead of manually editing the code itself.
